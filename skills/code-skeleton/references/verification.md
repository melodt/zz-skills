# Verification and Failure Handling

## Layers

- `syntax`: 解析、格式化或最小静态检查。
- `unit`: 受影响模块的单元测试或测试骨架可执行性。
- `build`: 类型检查、编译或打包。
- `integration`: 需要真实或本地替身依赖的集成检查。

先执行受影响范围内的最低必要层级；只有失败、共享基础设施变化或影响范围无法限定时才扩大验证。每条命令记录来源、超时、结果和证据。

## Failure classes

| 类别 | 默认处理 |
|---|---|
| 输入缺失 | 详细设计或对应正式测试用例缺失时阻塞受影响范围；其他缺失按影响记录，不能猜测公共契约 |
| 文档冲突 | 列出双方、影响和待决策项，阻塞受影响 ticket |
| 代码冲突 | 保护人工修改，局部补丁或跳过并报告 |
| 生成失败 | 停止当前 ticket，保留诊断产物 |
| 验证失败 | 记录失败，修复具体问题；无法修复则 `partial` 或 `failed` |
| 环境不可用 | 使用本地替身，明确未执行的外部验证 |

任何未解析模板变量、猜测性公共接口或真实凭据访问都属于阻塞项。

逐项检查设计、验收标准及测试用例与骨架的映射，核实接口、字段、状态和分支符合已确认契约。骨架检查通过只证明相应骨架检查结果；功能用例通过必须有实际执行及有效证据。未执行、受阻或预期未确认的用例不能算通过；保留结果和历史。
