# 系统操作手册 Skill 设计

## 目标

提供一个可主动调用的 `operation-manual` skill，在代码任务完成后按 Git 提交增量维护项目级系统操作手册。手册面向业务人员和系统管理员，以真实页面截图配合中文操作步骤说明系统功能。

## 已确认决策

- 每个项目维护自己的完整手册；skill 可跨项目复用。
- 首次调用盘点功能目录，后续从 `manifest.yml` 的 `source.checked_commit` 增量分析到当前源码 `HEAD`。
- 手册默认位于目标项目的 `docs/operation-manual/`，包含 `index.md`、`manifest.yml`、`sections/`、`assets/screenshots/` 和 `archive/`。
- 第一版以 Web 管理后台为主；浏览器自动化是可选采集能力。
- 截图优先来自真实验证环境；无法运行、登录或安全遮盖时，记录具体待补事项。
- 后端只有在改变页面、字段、校验、权限、状态、错误提示或其他用户行为时才更新业务手册；纯内部改动不进入用户手册。
- 手册按用户任务组织章节，每项包含角色、前置条件、路径、步骤、截图、结果、异常、权限和验证记录。
- 删除或重命名功能默认归档原章节，保留历史说明和截图。
- 更新成功后创建独立手册提交；工作区存在无关改动时不提交。
- 只有真实证据支持的内容才标记为 `covered`；不确定项保持 `pending`。

## 后端变更建议

使用 manifest 中的稳定 `function_id` 作为关联主键。skill 通过路由、菜单、权限配置、页面组件、OpenAPI 或 API 差异推断受影响功能；不要求给内部后端函数增加手册注解。无法判断某个接口是否影响用户时，列为待人工确认项。

## 运行结果

每次运行报告更新的功能、未完成的待补事项、commit 范围、实际验证方式、生成目录和手册提交 ID。即使存在待补事项，也可以记录已完成影响分析的源码 commit，避免下次重复扫描。
